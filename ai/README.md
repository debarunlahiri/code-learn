## How to use the material

- Explain each answer aloud in two minutes or less.
- Run every coding solution and add edge-case tests.
- For design questions, state assumptions before choosing components.
- Connect each topic to a real project, production incident, or measurable result.
- Revise metrics and trade-offs rather than memorizing definitions alone.

## A useful answer structure

For a conceptual question, explain the definition, intuition, practical example, limitation, and trade-off. For a design question, begin with requirements and scale, then cover data, modelling, serving, monitoring, failure handling, security, and cost. For a coding problem, clarify inputs and edge cases before writing a simple correct solution, then discuss complexity and possible optimization.
